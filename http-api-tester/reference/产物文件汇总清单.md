## 二、调用链分析文档（必需）

| 产物项 | 文件名 | 用途 | 指定文件路径 |
|--------|--------|------|--------------|
| 调用链分析文档 | `call_chain_analysis.md` | 完整的调用链分析文档，包含所有发现的API端点列表、端点之间的调用关系、参数依赖关系、识别的测试场景列表、最大依赖链识别、角色分析、跨角色调用链 | 测试框架标准分析目录：<br>- Python: `tests/analysis/`<br>- Java: `src/test/analysis/`<br>- Node.js: `tests/analysis/` 或 `__tests__/analysis/`<br>- Go: `tests/analysis/`<br>- Rust: `tests/analysis/` 或 `src/analysis/` |

## 三、测试文件组织（必需）

| 产物项 | 文件名 | 用途 | 指定文件路径 |
|--------|--------|------|--------------|
| 原子层测试文件 | `{module}.py` 或对应语言扩展名 | 单个API端点测试，按业务模块命名（如 `order.py`） | `testcases/atomic/` |
| 业务层测试文件 | `test_{核心业务模块}.py` | 完整业务流程测试，包含多个端点的调用链测试 | `testcases/` |
| 最大依赖链测试文件 | `test_max_dependency_chain.py` | 针对系统中识别的最大依赖链的专门测试文件 | `testcases/` |

**命名规则**：
- 原子层：直接使用业务模块名称，如 `order.py`
- 业务层：使用 `test_核心业务模块.py` 格式，如 `test_order.py`

## 关键约束提醒

1. **静态分析探针**：必须在 `scripts/` 目录下实现，使用语言特定的静态分析库
2. **分析文档**：必须位于测试框架标准分析目录下
3. **测试文件**：必须按 `testcases/atomic/` 和 `testcases/` 结构组织
4. **报告模板**：`report.html` 或 `report_enhanced.html` 和 `assets/` 目录必须复制到报告目录
5. **数据文件原则**：一次会话一份完整数据文件、全量数据文件、非增量更新
